# 01 · 需求理解

## 1. 用户与场景

**用户**：品牌/内容运营。手上有一个活动主题、一笔预算、一个截止时间，需要在截止前拿到一份
"能直接开工"的方案：选哪个制作档位、花多少钱、用哪些素材、脚本长什么样、方案存在哪。

**现状痛点**（也是这个 Agent 要解决的）：

1. 预算和时间是硬约束，但运营常常先给主题、后补预算（本次就有 1 个用例是缺预算）。
2. 素材库、脚本工具、计费系统是分开的，任何一环抖动都会让"排好的计划"失效。
3. 撞到预算上限时，人不一定知道下一步该退到哪个档位；工具报错时，容易整单重来、丢掉已做的部分。

**目标**：把"选档位 → 算钱 → 拿素材 → 写脚本 → 存档"这条链路交给 Agent 跑，
并且**在约束被打破时做出可见的调整**，而不是机械地把 5 个函数串一遍。

## 2. 范围

### 做

| 能力 | 说明 |
| --- | --- |
| 预算内选档 | 三个档位（完整/精简/极简）逐项现算费用，选第一个满足预算与工时的 |
| 工时约束 | 用"距截止时间 − 缓冲"得到可用分钟数，档位耗时超标同样要换档 |
| 缺信息拦住 | 缺主题/预算/截止时间时停下要信息，并支持补齐后从断点续跑 |
| 工具失败处理 | 原地重试 1 次 → 仍失败则降级档位或收尾；失败步骤不记成功 |
| 部分成功处理 | 素材只拿到一部分时，按实际条数重算费用再决定是否继续 |
| 幂等保存 | 同一份内容重复保存返回原方案，不产生重复文件 |
| 硬上限 | 步数 / 工具调用次数双上限，到顶返回明确的未完成状态 |
| 可审计 | 每步记录动作、参数、返回摘要、后续动作、决策依据；落检查点 |

### 不做（有意留白）

- **界面 / 线上部署 / 多 Agent / 生产级 Runtime**：考核说明中非必需，且 3 小时预算内
  做界面只会稀释对决策链路的验证。
- **真实模型的效果评估**：本机无模型密钥，真实模型路径只保证"接得上、解析得住"，
  效果结论不成立（详见 03 文档第 5.2 节）。
- **真实素材版权与真实计费**：数据全部合成，避免隐私与版权问题。

## 3. 成功标准

| 编号 | 标准 | 怎么验 |
| --- | --- | --- |
| S1 | 一条需求能在预算内产出完整方案（计划 + 素材 + 脚本 + 落盘路径 + 费用明细） | `examples/case-01-normal/` |
| S2 | 预算 10、完整版 12 时，能自己改选 8 的方案并交付 | `case-01` 的 step2→step3 |
| S3 | 没有可行方案时返回未完成与缺口，不落盘 | `case-06`（缺口 1.0） |
| S4 | 缺预算时停下要信息，不编数字 | `case-02` |
| S5 | 工具连续失败时改计划，且保留已成功的素材与估算 | `case-04`（11 步完成） |
| S6 | 重复执行不产生重复方案 | `case-07`（`deduped: true`） |
| S7 | 达到步数上限返回 `INCOMPLETE_LIMIT` 并说明保留了什么 | `case-08`（3/3） |
| S8 | 失败步骤在记录里必须是失败，不能算成功 | `tests/test_agent_loop.py::TestToolFailure` |
| S9 | 交付结果含任务计划、步骤状态、费用合计、方案或未完成原因 | `result.json` 的 `plan.outline` / `steps_brief` |
| S10 | 失败步骤可从检查点续跑，且不重跑已成功步骤（加分项） | `case-11` → `case-12` |

## 4. 验收点映射（题目"必须验收" → 证据）

| 题目验收点 | 本仓库对应 | 证据文件 |
| --- | --- | --- |
| 正常完成 | 12 超预算 → 8 交付 | `examples/case-01-normal/` |
| 缺预算或截止时间 | `NEED_INPUT` + 续跑 | `examples/case-02-missing-input/`、`case-03-resume-after-input/` |
| 工具失败 | 脚本服务连续 503 | `examples/case-04-tool-failure-degrade/` |
| 预算超限 | 全档位被否 + 缺口 | `examples/case-06-budget-exceeded/` |
| 重复执行 | 幂等保存命中 | `examples/case-07-repeated-save/` |
| 步数上限 | 3 步强行截断 | `examples/case-08-step-limit/` |
| 加分：失败步骤续跑 | 落盘失败 → 续跑只补这一步 | `case-11` → `case-12`（第 9 步直接 save_plan） |
| 加分：缺信息续跑 | `resume --set budget=10` | `case-02` → `case-03` |
| 加分：部分成功保留 | 素材 1/4 时重算并交付 | `examples/case-05-partial-materials/` |

## 5. 输入与数据

- `data/costs.json`：5 项单价（素材授权/脚本/配音/剪辑/审核）、3 个档位规格、工时参数。
- `data/materials.json`：18 条合成素材，带标签，供检索与素材不足场景使用。
- 任务输入：`{topic, budget, deadline, tone, audience, notes}`，其中前三项为必填。
