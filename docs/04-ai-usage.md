# 04 · AI 使用记录

> 原则：写清"哪些是 AI 产出的、哪些是我判断的、哪些我只验证了一半"。
> 本文只记录能对应到仓库文件的事实；没有验证过的效果不写成结论。

## 1. 用了什么

| 项 | 内容 |
| --- | --- |
| 工具 | AI 编程助手（对话式 Agent，可读写文件、执行命令） |
| 使用方式 | 我先定题目（内容任务规划 Agent）与验收清单，再让 AI 按模块产出代码/测试/文档，我逐轮验收 |
| 未使用 | 未使用 AI 生成图片/视频；未把密钥、个人隐私、真实素材交给模型 |
| 代码来源 | 本仓库 `src/`、`tests/`、`scripts/`、`docs/` 初稿由 AI 生成，我做了下述判断与验收 |
| 提交前一轮 | 由 AI 助手按考核清单做规范性自查（重复代码、文档占位符、命令可复现性、交付字段），我要求以仓库实际产物为准逐项复核 |

## 2. AI 承担的部分

| 模块 | AI 产出 | 我的处理 |
| --- | --- | --- |
| `src/tools.py` | 5 个工具、成本公式、故障注入、保存前二次核算、参数防御 | 核对了单价表与手算结果（12/8/5 三档），确认公式与 `data/costs.json` 一致 |
| `src/planner.py` | `MockPlanner` 策略、`LLMPlanner` 与 JSON 解析 | 要求把"降级"写成可审计的 `decision_basis`，不接受只写"失败了" |
| `src/agent.py` | ReAct 循环、双上限、检查点、收尾校验、跨规划器台账 | 追加"假完成拦截""工时越界也拦截""LLM 路径不能丢被否方案"三条要求 |
| `src/cli.py` | `run` / `resume` 子命令、`--now` 固化时间、Mock 提示 | 要求 `--now`，否则"可用分钟"每次都变，实施例无法复现 |
| `tests/` | 56 个用例 | 要求费用测试必须手算复算，不能只断言常量 |
| `scripts/fake_llm_server.py` | 本地 OpenAI 兼容端点 | 我要求"LLM 路径不能只写不跑"，用它把 HTTP + 解析 + 循环真跑一遍 |
| `scripts/gen_examples.py` | 13 个实施例一键重跑 + 状态核对 | 要求任一用例状态不符就返回非 0，避免"证据漂移" |
| `scripts/verify_submission.py` | 提交物自检 | 不跑模型，只核对目录、交付字段、trace 与必验场景 |
| `docs/` | 五份文档初稿 | 逐条核对文中数字与 `examples/` 实际文件一致 |

## 3. 我做掉的判断（AI 只给了方案，选哪个是我定的）

1. **运行方式选 CLI，不选 HTTP API / Notebook**：评审给一条命令就能跑；API 要多守一个进程，
   Notebook 的"隐藏状态"会让"实际输出"不可信。
2. **原生实现，不套 LangGraph / ADK**：题目说框架名不加分，而本题核心（状态机、上限、失败处理）
   正好是框架藏起来的部分。代价是代码多一点，收益是每一步都能指给人看。
3. **默认离线规划器，真实模型做成可替换的第二实现**：本机没密钥，不能交一个"评审跑不起来"的仓库；
   同时明确标注 mock 不证明真实决策效果，避免把"流程通"包装成"模型好"。
4. **上限定 12 步 / 12 次调用**：正常链路 7 步、最复杂的失败用例 11 步，12 既兜住异常又不会过紧。
5. **不做界面和部署**：考核说明里非必需，3 小时预算内优先把决策链路和证据做扎实。

## 4. 我怎么验证 AI 的输出（不是"看着像对"）

| 验证手段 | 具体做法 | 结果 |
| --- | --- | --- |
| 跑通 | `python scripts/gen_examples.py` 重跑 13 个用例 | 13/13 状态与退出码符合预期 |
| 单测 | `python -m pytest tests -q` | 56 passed |
| 提交物自检 | `python scripts/verify_submission.py` | 全部检查通过（目录、字段、trace、必验场景） |
| 手算复核 | 按 `data/costs.json` 单价手算三档费用，与 `estimate_cost` 对齐 | 12.0 / 8.0 / 5.0 一致 |
| 负向测试 | 写一个"什么都不做就宣布完成"的假规划器 | 被改判为 `INCOMPLETE_INCONSISTENT` |
| 工时负向测试 | 产物齐全但 12 分钟 > 可用 10 分钟 | 被改判为未完成，理由写明工时越界 |
| 伪造检查 | 故意让 `save_plan` 收到错误 `cost_total` | 被拒绝保存，目录为空 |
| 数字抽查 | 文档里每个数字回查对应 `result.json`/`trace.json` | 修正过 1 处（见第 5 节第 3 条） |

## 5. AI 出错、我拦下来的地方

下面这些是真实发生过的，也是我认为这份记录有价值的部分：

1. **续跑把新输入覆盖掉了**：AI 首版 `Agent.run` 在 `resume` 时优先用 `state.json` 里的旧任务，
   导致 `--set budget=10` 不生效，补齐预算后仍然 `NEED_INPUT`。我跑 `case-03` 看到两次连续
   `request_input` 才发现。改为"以调用方任务为准，检查点只保留进度"。
2. **幂等被自己污染**：首跑 `case-01` 就出现 `deduped: true`，因为上一轮试跑已存过同一方案。
   这说明实施例共享目录却没有清场。改为 `gen_examples.py` 先清空方案目录并按固定顺序执行。
3. **文档数字与产物对不上**：初稿把 case-04 写成"素材 4 条"，实际注入后只拿到 2 条（12.0 重算为 10.8）。
   回查 `result.json` 后改正。
4. **降级没有留痕**：AI 首版降级只改内部状态，`rejected` 里没有记录"为什么放弃 full"。
   我要求补一条 `{"reason": "脚本工具连续失败 2 次，放弃该方案"}`，否则评审只看到方案变小、看不到原因。
5. **交付结果缺"任务计划"和"步骤状态"**：对着题目逐条核时发现 `result.json` 只有方案和费用，
   没有工序清单、没有每步成败。补了 `plan.outline` 与 `steps_brief`。
6. **续跑其实是重跑**：我检查 `case-03` 的第 2 步动作，发现它又从 `list_plan_variants` 开始，
   说明 `last_action` 没进检查点。补上后 `case-12` 才做到"只补失败那步"。
7. **接 LLM 规划器时收尾校验误判**：任务已完成却被判 `INCOMPLETE_INCONSISTENT`，
   原因是校验只读 mock 的私有状态。改成 Agent 侧统一的 `progress` 台账。
8. **LLM 路径丢掉"被否方案"**：`case-10` 里 full 12 被否、lite 8 交付，但 `result.rejected` 是空的，
   因为被否记录只写在 MockPlanner 的 scratch 里。改为 Agent 按真实估算结果自动记账，
   并在 LLM 的输入里带上 `rejected` / `chosen_variant` / `same_tool_failures`。
9. **收尾校验只查预算不查工时**：一个 12 分钟的方案在"可用 10 分钟"时仍可能被模型宣布完成。
   补上工时校验，并加了对应负向测试。
10. **提交前发现重复代码与占位符**：`agent.py` 有一段重复的 `chosen_variant` 赋值，
    `test_tools_cost.py` 末尾整段重复了两个测试类（后者覆盖前者，实际是死代码），
    `05-retrospective.md` 有一节重复，`04-ai-usage.md` 留着"待本人确认"占位符。
    这些不影响运行，但会影响评审对工程习惯的判断；已全部清理，并让
    `verify_submission.py` 检查文档占位符、`gen_examples.py` 检查实施例状态。

## 6. 我没有让 AI 替我做、也不敢断言的事

- **真实模型效果**：没有密钥，`--planner llm` 只验证到"能构造请求、能解析返回、循环能跑完"。
  "大模型会不会也选 8 的方案"我没有证据，所以 `docs/03` 把它列进未验证项，而不是写"已验证"。
- **业务正确性**：单价表是我编的合成数据，不代表小影真实报价体系；
  真实场景下 `costs.json` 要被业务替换。
- **脚本质量**：模板拼装只保证结构完整，不保证文案可用。
